# Getting started

[Desktop toolkit](desktop.md) · [Examples](../examples)

## Requirements

The integration gates currently cover Windows x64. Source development and
builds require Rust/Cargo, the Windows C++ build tools and Zolo's ordinary
Rust provider. The resulting embedded application does not require those
source build tools on its deployment machine.

Use a current Zolo build and matching Rust provider/editor server. The required
`extern rust`, `std::ui`, `TaskGroup`, `@naming` and `@reify` support is in
[Zolo main at d400dee69 or a compatible later revision](https://github.com/devzolo/zolo-lang/tree/d400dee69ee152a971a8e17419d0cf6ac5565ad6).
Older installations with the same `0.1.8-alpha` version label may lack these
features; the version label alone does not establish compatibility.

The repository's verification scripts also require the structured command and
finite stream APIs in [Zolo bd647c2](https://github.com/devzolo/zolo-lang/commit/bd647c2) or later.
See [the script guide](../scripts/README.md) for tooling requirements.

## Add GPUI to your application

Create `zolo.toml` in your project:

```toml
[project]
name = "my-desktop"
version = "0.1.0"
entry = "main.zolo"

[dependencies]
gpui = { git = "https://github.com/devzolo/zolo-gpui.git", rev = "main" }
```

Create `main.zolo` alongside it:

```zolo
use gpui::{run, state, Node, Column, Text, Button, Style}

let count = state("counter", 0)
fn Counter() -> Node {
    <Column style={Style.new(padding: 24.0, gap: 16.0)}>
        <Text value={"Count: {count.value}"} />
        <Button on_click={|| { count.value += 1 }}>Increment</Button>
    </Column>
}
run(Counter, title: "My desktop", width: 640.0, height: 360.0)
```

Then install and start a persistent development session:

```powershell
zolo install
zolo dev main.zolo
```

Save `main.zolo` to update the same window while keeping the named state.
UI saves reuse the loaded native adapter; the first preparation can take
several minutes and reports its progress. Restart after changing Rust source
or dependencies. See the [measured development behavior](desktop.md#persistent-development).

Keep the generated `zolo.lock` with your application. For a release, pin `rev`
to the full tested library commit rather than the moving `main` branch.
The library's local preparation locks are generated by `zolo install` and
are not distributed as consumer locks.

## Build an application for distribution

From your application directory:

```powershell
zolo build main.zolo --emit native --plugins embed -o target/my-desktop
```

The resulting Windows executable embeds the native provider and adapter.
LLVM is also supported with `--emit llvm`. The verified deployment environment
has no source package, installed plugin paths or Rust compiler available.

## Develop the library locally

When changing the library alongside your app, replace its Git dependency:

```toml
[dependencies]
gpui = { path = "../zolo-gpui" }
```

Paths are relative to the application's manifest. Run `zolo install` after
changing the dependency declaration. The repository's examples deliberately
use a path dependency so changes to the checkout are exercised locally.
